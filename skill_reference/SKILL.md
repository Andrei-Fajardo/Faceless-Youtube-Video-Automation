# Art Short

The user invokes this skill and names a painting (for example `/art-short The Night Watch`). Everything after the skill name is the painting. Run the whole pipeline with no approval prompts and no questions, in the style of the finished test run on *The Night Watch*. The only things you may stop for are in "Stop conditions". **Never publish or upload anything**: the output is a review packet.

Project: `<repo-root>` (git repo, Python 3.12 venv in `.venv`). Reference run (the model to imitate): `reference/the-night-watch/` next to this file (`script.json`, `video.json`, `claims.json`).

## Shell conventions (these avoid failures seen in the test run)
- Use the Bash tool. Start every shell command with:
  `cd "<repo-root>" && export PYTHONIOENCODING=utf-8 HF_HUB_DISABLE_SYMLINKS_WARNING=1 HF_HUB_OFFLINE=1 PATH="/c/Program Files/File Converter:/c/Program Files/Tracktion/Waveform 13:$PATH"`
  and run Python as `.venv/Scripts/python.exe tools/<name>.py`. ffmpeg/ffprobe are not on the default PATH.
- Never write long files with a bash heredoc (it breaks). Use the Write tool.
- HyperFrames: `npx --yes hyperframes@0.8.214 <command>` from `video/`. Render to a NEW file name (`out/final_v<N>.mp4`): Windows refuses to overwrite a file another program has open.
- Never print, cat, or paste `.env` or the API key. `tools/` scripts read it; you never need to.

## Stop conditions (the only reasons to stop and ask)
1. `tools/preflight.py` fails. If only `voice_id` is empty: ask the user ONCE for the voice ID (ElevenLabs > the voice > Copy voice ID), write it to `tools/eleven_config.json`, and carry on. The API key is restricted, so voices cannot be looked up by name.
2. The painting is not public domain (artist died less than ~100 years ago, or no public-domain image on Wikimedia Commons), or facts for a good script cannot be verified. Say so and suggest alternatives; do not make a weaker video.
3. An ElevenLabs spend guard trips (`tools/eleven_tts.py` prints `STOP:`) or the API returns an error. Report the exact message.
Anything else: decide, do, and report afterwards.

## Pipeline

**0. Preflight and new run**
- `tools/preflight.py` (free). Then `tools/start_run.py <kebab-slug> "<Painting title>"`: archives the previous run into `runs/` and creates clean working folders.

**1. Research (sourced facts only)**
- Channel format: one odd moment, the real story behind it, and a joke on the way out.
- Use WebSearch/WebFetch on museum and scholarly sources (the museum's own pages first; Wikipedia only for the commissioning and dating basics). Every claim spoken in the narration goes in `script/claims.json`: `{id, narration, source_url, paraphrase, verification}` with `verification` = `fetched` (you read the page text) or `snippet` (search-result quote only; say so). If a claim cannot be verified, rewrite it more cautiously or cut it. Never invent a source or a quote. Prefer the museum's exact wording for titles and dates. Do not state anything stronger than the source says (the test run softened "the grime lifted" to "a cleaning ... changed that" for this reason).

**2. Image**
- `tools/painting_prep.py fetch "File:<Commons file name>"` (refuses non-public-domain labels, writes `assets/credits.json`). Confirm the artist's death date and the collection credit yourself. Wikimedia thumbnails stop at 3840 px: for a small zoom target add `--original` (downloads the full-resolution file; ffmpeg cannot decode very large JPEGs, the tool uses Pillow).
- `tools/painting_prep.py prep` (or `prep --maxw 6400` when the file is large) builds `video/assets/painting.jpg` and `bg.jpg` and records the size in `script/video.json`.
- View `video/assets/painting.jpg` with the Read tool, then crop the region you think holds the detail (Pillow, into the scratchpad) and view that too: you cannot place a small detail from the overview. Note its centre as fractions of the full image.
- For a zoom above about 5x, make a full-resolution crop: `tools/painting_prep.py detail x0 y0 x1 y1` (fractions; about 7% of the width and 22% of the height around the focus at 14x). `build_video.py` lays it exactly over the painting so the zoom is sharp. Measure, don't trust, the first estimate (see step 6).

**3. Script and visual config (write both with the Write tool)**
- `script/script.json` (v2). Follow the reference. Rules: 100-110 words (this voice reads about 2.8 words per second, so a 50 s Short needs about 105 words including pauses; 95 words gave a 43 s take); hook 8 words or fewer; sentences 12 words or fewer (average 8 or fewer); one idea per line; setup, then silence, then reveal; a question gets a pause before its answer; surprising word last; no em dashes, semicolons or ellipses; spell numbers and dates as spoken ("sixteen forty-two"); fragments are fine; the last line is the joke. Each line: `id, text, beat (hook|setup|question|reveal|punchline), speed, pause_after_ms, onscreen, visual, claims`. Use `tts_text` where the voice needs a respelling or a comma-pause (for a name the voice may mangle, put the respelling in `tts_text` and keep the true spelling in `text`, e.g. Kröller-Müller as "Kruller Muller"; `tools/lexicon.json` maps awkward names, e.g. "Banninck Cocq" to "Banning Kok"; add new ones).
- The script must contain: a "Look at the <detail>." line (the zoom beat), a line stating the painting's date (year overlay), a line that speaks the painting's official title (the title card, `onscreen` holds the exact museum wording), and a closing run of lines that restates the premise.
- `script/video.json` (see the reference): `hook` (3-5 words, the odd claim), `closing` (2-4 words restating the premise, `from_line` = the first closing-narration line so it stays on screen at least 2 seconds, ideally 4-5), `year`, `zoom` (`line`, `focus` fractions of the image, `screen` where it lands, `scale` about 3 for a large detail up to 14 for a tiny one, `pullback_line` = the last line to stay zoomed for, optional `detail` box), `fun` (REQUIRED for every video, see "Motion and edit style"; reference with shots and reference cards: `reference/the-garden-of-earthly-delights-motion/video.json`): `bounce` + `emphasis` (words shown in gold, with a small pop as they are spoken), `hook_ring` (a pulsing ring and label on the painting at frame 0, pointing at the zoom target: `focus` fractions, `label`), `callouts` (labels with an arrow on the zoom frame: `line`, `text`, `tip` screen x/y MEASURED from a snapshot, `dir`), `pops` (`kind` num = big gold number such as a year, `card` = a tilted headline card for a quote, `stamp` = a slammed red word; each with `line`, optional `word` to time it on, `text`), and `montage` (rapid whip-cuts through 3-5 of the painting's strangest details while a line is spoken: `line`, `word` to start on, `points` as fractions of the image, `scale` about 5, `screen` where each detail lands, `stamp` word slammed at the end, `stamp_y` below the details), `shots` (the camera shot list, see below), and `refs` (reference cards, see below). Pick the strangest details by cropping candidate regions and viewing them. Never add sound effects for any of this. `title_card` (`line`; optional `lines` for explicit line breaks and `font_size`, e.g. 96 for a short title), optional `end_hold` (seconds of silent final hold; use it to reach 50 s instead of stretching the voice), and `veil` ONLY if the story is about darkened varnish or dirt (otherwise omit it; the picture then simply pushes in and pulls back). `painting` size is filled by `painting_prep.py prep`.

- `script/post.json`: the post copy for YouTube Shorts, TikTok and Instagram Reels (see the reference). Write it AFTER the script and from `claims.json` only: never promise or imply more than the script says. YouTube: three title options (first = recommended; plain, truthful, includes the painting's name, under 100 characters, no all-caps or fake urgency), a 2-3 sentence description, 4 hashtags starting with `#Shorts`. TikTok: one or two short sentences plus 5 hashtags (include `#learnontiktok`). Instagram: a hook line, one short paragraph, 5 hashtags. `tools/make_packet.py` appends the sources, the painting credit, the synthetic-voice line and the hashtags and writes `out/review/post_copy.md` (paste-ready, with character counts) and `description.txt`.

**4. Voice (ElevenLabs; the voice is never processed)**
- `tools/eleven_tts.py --dry-run` (free; check the character count), then `tools/eleven_tts.py` (one paid call; guards enforce the per-call cap, the per-run call cap and the monthly budget; identical text is cached).
- `tools/ingest_voice.py` (aligns the take to the script lines with per-burst whisper; measures the real pauses), then `tools/make_cues.py`.
- If the take is more than a few seconds under 50 s: first extend the script with one or two more sourced lines (this is the run's second and last paid call; edit `script.json` and `claims.json`, re-run `eleven_tts.py`), then reach the gate with silence only: `tools/ingest_voice.py`, then `tools/edit_voice.py --pad-to 50.3` (spreads extra silence over the pauses, voice copied untouched; it needs a 1-1.5 s `end_hold` in `video.json` first), then `tools/make_cues.py`. Never a long silent hold, never a stretch.
- `tools/pacing_report.py`: words/sec 2.1-2.5, silence 15-22% are reported but are NOT enforced. The user chose the raw take over fixing the pace. **Never time-stretch, EQ, compress, de-ess or limit the voice.** To change pace, regenerate once at a different `--speed` (only if the model honors it; `eleven_v4` barely does). Never regenerate more than once.

**5. Sound design (exactly this, nothing else)**
- `tools/sfx.py`, then `tools/mix.py`. The mix contains the untouched voice, the quiet ambient bed (ducked under speech), a small boom at 0.00 s, and the rising warp into the zoom. The user rejected every other effect (swell, wipe, settle, pull-back and title whooshes): do not add any. Effects are leveled against the voice's RMS and sidechain-ducked under speech. Master: -14.5 LUFS stereo, true peak below -1 dBTP. Copy `out/review/audio_only.wav` to `video/assets/mix.wav`.

**6. Video**
- Motion check: count the shots. There should be about one per spoken line plus the montage cuts, and no stretch of more than about 3 seconds without a camera move, a pop or a card. Fewer than that means the video is too static: add shots before rendering.
- `tools/build_video.py`, then from `video/`: `npx --yes hyperframes@0.8.214 check` (0 errors required), then `npx --yes hyperframes@0.8.214 snapshot --at <cue times, the zoom landing, title, closing, last frame>` and READ the contact sheet. Verify: hook text on frame 0; the zoom lands on the chosen detail: MEASURE where the detail appears in the zoom frame; if it sits `d` px below its `screen` target, add `d / (scale x painting height in video px)` to `focus` y (subtract if above; same for x with the width). Rebuild and re-snapshot until it lands on target; the title block is large, fully visible and inside 80% of the width; the closing caption is on screen at least 2 seconds and does not overlap the painting; the last frame matches frame 0.
- Render: `npx --yes hyperframes@0.8.214 render -o ../out/render_v<N>.mp4 --fps 30 --quality delivery`, then `tools/mux_audio.py out/render_v<N>.mp4 out/final_v<N>.mp4 --reencode` (re-encodes the video once with x264 CRF 19 so a heavily animated render drops from about 170 MB to a sane size, and encodes the lossless mix to AAC once at 224 kbps; the renderer's own AAC can fall under the 192 kbps gate). Without `--reencode` the video is copied untouched.

**7. QA and packet**
- `tools/qa.py out/final_v<N>.mp4` (duration 50-60 s; if the take is a little short, set `end_hold` in `video.json`; format, loudness, true peak, silent gaps, black/freeze, caption timing, claims, credits, loop). Fix any failure and re-render before reporting.
- Write `out/review/improvements.md` (what you would improve next, plus anything unverifiable), THEN run `tools/make_packet.py out/final_v<N>.mp4` (writes `post_copy.md` and a permanent copy in `finished/<slug>/`). `git add -A` and commit.

## Motion and edit style (required; the user prefers this much more than a still painting)
The video must never look low effort. It needs a fair number of edits, constant gentle motion, and smooth transitions. Build it with `fun.shots`, `fun.pops`, `fun.callouts`, `fun.refs`, `fun.hook_ring` and `fun.bounce`, and view the result before rendering.
- **Shots (`fun.shots`)**: one entry per line or per beat, so the camera changes about every 2 to 3 seconds and never holds the same framing longer than about 3 seconds. Each: `line` (or `at: {line, word, dt}` to start on a spoken word), `view` (`"whole"`, `"up"` for the title lift, or `[fx, fy]` as fractions of the image), `scale`, `end_scale` (a slow drift inside the shot), `screen` where the focus lands, and `transition`: `zoom` (a long dive in, 1.6 s), `smooth` (a slide, 0.55 s), `slow` (0.9 s), `whip` (a fast pull back or punch-in, 0.22 s) or `cut`. Mix them: dive in on the first detail, slide between details, whip back out to the whole painting for dates, whip in again for the reveal. Use scale 3.2 or more for any detail shot (a smaller scale shows empty background above and below a landscape painting). The first shot starts from `whole` at 1.0 and the last shot must end on `whole` at 1.0, so the loop is seamless. Use a `whole` shot of the lifted `up` view for the title card and drop back to `whole` about 0.5 s before the closing caption.
- **Fast montage**: when the narration says the painting is strange, hidden or full of detail, whip-cut through 3 to 5 of its strangest details (one shot each, 0.7 s apart) and slam a stamp word at the end.
- **Pops**: every year, number and quote that is spoken gets an on-screen pop (`num`, `card`, `stamp`), timed on the spoken word.
- **Reference cards (`fun.refs`)**: whenever the narration cites a person, a document or a source, show it. A card slides in with: `tag` (SOURCE, THE PAINTER, FIRST RECORD), `label` (the name and the year or role), `text` (the exact quote or document title, in quotation marks), `source` (where it came from) and, when a public-domain image exists, `image` (a portrait or a manuscript page). Get the image with `tools/painting_prep.py ref "File:<Commons name>" <short-name>` (public domain only, credited automatically; for example the Recueil d'Arras portrait of Bosch). For a living or private person never use a photo and do not name them if the narration does not: use a text card with their role and the source. Do not invent a quote or a portrait: if no public-domain image exists, make a text card.
- **Captions**: gold emphasis words and the small pop (`fun.bounce`, `fun.emphasis`).
- **Graphics layer (required, all in `fun`)**: `vignette`, `progress` (a thin gold progress bar that fades in after frame 0 and out before the last frame so the loop matches), `bg_drift` (the blurred background drifts and returns: parallax), `flash` (a soft white flash, 0.14, on every whip cut), `wipes` (a gold colour-wipe bar sweeping across at the big scene changes: `at: {line, dt}`; use about 3 per video, never in the montage), `circles` (a gold ring that draws itself around a detail and follows the painting as the camera moves: `line`, `focus`, the camera `scale` at that moment, `radius` in screen pixels, `delay`/`dt`/`word`), `swatches` (colour chips for a colour story, with an optional struck-through `strike` chip, such as BLACK), pop kinds `num`, `card`, `stamp` and `timer` (a filling ring for a duration, text `"30|MIN"`). Use at least: a hook ring, 2 circles or callouts on the key details, 3 wipes, 3 pops, and every cited source as a reference card.
- **Placement**: on tall paintings the reference cards go to the top of the frame (the generator does this when there is no room under the captions), number pops move down to y 470, and the closing caption owns the top slot, so give any card shown during the closing lines a `y` of about 330. Cards shown while the camera is zoomed on the sky or the top of the painting need `y` about 1000 so they do not cover the detail. Never stack two overlays on the same lines.
- **Never** add sound effects for any of this.

## Hard rules learned in the test run
- The premise must land by the end: "Not night. Daylight."-style closing text needs at least 2 seconds, placed over the closing narration, handing back to the hook text in the last half second so the loop is seamless.
- Titles are revealed all at once as a large block (72 px, four lines of at most 21 characters), never scrolled.
- Captions are 2-4 words, current word bright, from the script's spelling.
- Effects never sit at or above the voice level while it speaks.
- No fabricated, uncited facts. Public-domain images only, credited.
- Respect spend guards. One ElevenLabs paid call per run is normal; two is the maximum.

## Content cautions
- Painted nudity is common in the Old Masters: say in the report that TikTok/Instagram may limit reach or age-gate it, and that YouTube normally allows it in an educational context.
- If a popular story about the painting is contested (a viral "discovery"), tell it as contested and attribute each side; never present one researcher's argument as settled fact.

## Final report (short, honest)
Give: the painting and the odd-moment hook; the PERMANENT paths `<repo-root>\finished\<slug>\final.mp4` and `...\post_copy.md` (never `out/`: the next run moves it into `runs/`) (quote the recommended YouTube title); duration, loudness, QA gates; ElevenLabs characters used; claims with only `snippet` verification; pacing numbers if outside the targets; anything you cannot judge without hearing (pronunciation of names, the voice itself); open risks (the ElevenLabs plan's commercial-use terms for the chosen voice). Do not claim the audio sounds good: you cannot hear it.
